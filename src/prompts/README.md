# 提示词分类与装配

| 类别 | 位置 | 职责 |
|------|------|------|
| Agent 通用规则 | `system/agent.ts` | 助手职责、工具使用原则、事实与执行状态的表达 |
| 任务指令 | `tasks/storyboard.ts` | 分镜创作、修改、业务要求及输出 JSON 协议 |
| 工具说明 | `../tools/*.tool.ts` 的 definition | 各工具的用途、适用条件、参数和能力限制 |
| 用户需求 | Web 请求或当前任务输入 | 当前用户具体要完成什么，不在源码中按剧情逐份存放 |

工具不要求各有一份系统提示词。工具说明与实现维护在一起，注册表提供 definition，由 Gateway 放入 API 的 tools 参数；不重复复制到通用系统提示词。

分类依据是职责，不是 HTTP 协议里的 role。通用规则和任务规则可以按当前阶段组合进入 system 消息，用户具体需求进入 user 消息。

第四课的素材搜索演示只装配 agentSystemPrompt 与工具声明，不装配要求只输出分镜 JSON 的任务提示词。第三课的分镜提示词现移至 tasks/storyboard.ts，导出名仍为 storyboardPrompt，正文保留。

后续到分镜生成阶段再装配相应任务指令，不每次加载全部任务。普通文本、JSON 模式和工具选择由 Gateway 请求选项分别控制。Harness 的审批、预算和身份约束必须由程序落实，提示词不替代控制逻辑。

本次没有引入提示词路由器或自动阶段识别；先由代码明确选择当前需要的指令。
