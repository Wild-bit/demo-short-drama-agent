# 一句话开拍：短剧工坊学习与开发课程大纲

2026-11-21 更新。第七课已完成理解检查，第八课聚焦 Agent 工具循环的步数控制。第十课引入短剧项目。最新技术方案以[项目目标与范围](./project-goals-and-scope.md)为准。

分享主题：**《一句话开拍，Agent 在幕后忙什么？》**  
副标题：用短剧工坊拆解 Agent Loop、上下文管理与 Harness

## 1. 学完后交付什么

做一个规模受控的短剧工坊。输入剧情需求 → 展示可修改的剧本和分镜草案 → 观察 Agent 调用工具 → 确认镜头版本、模型和生成范围 → 提交生成任务 → 查看视频片段、费用与执行记录。

初期以三镜、约 15 秒片段作为演示案例，镜头数可由用户指定或由 Agent 建议，不写死在业务规则中；按预算再扩展到 30–60 秒小故事。完整拼接导出与逐镜预览分开验收，不把只有片段预览描述为已经生成完整成片。

- 文本主线：DeepSeek，具体型号与 API 协议在接入时确认。
- 视频候选：Seedance 2.5、Grok Imagine Video 1.5，先接通一家，再适配另一家。
- 学习重点：Agent 与 Harness 的关系、Loop、提示词装配、上下文管理与压缩、模型决策、工具执行。
- 全部覆盖：原截图 14 项，各有解释、代码或独立小实验及验证依据。
- 后期扩展：评测 Agent 和基于质量记录的模型路由，分享时介绍思路，当前不要求实现。

本阶段讲解单 Agent 编排。普通程序按依赖组织步骤，模型在允许范围内选择动作。动态拆任务、协调多个 Agent 的框架对照暂不安排。

### 第十课分三步验收

1. **建项目和关联会话。** 用户能创建、列出和重新打开自己的项目。一个项目可有多个会话，一个会话至多属于一个项目。为现有会话增加可空的 `project_id` 逻辑关联，旧会话继续按原入口使用。服务端核对项目和会话归属，拒绝跨用户访问以及项目与会话不匹配的请求。
2. **保存作品。** 项目保存剧本、分镜草案、版本和已确认的素材引用。镜头使用稳定标识，展示顺序可单独调整。修改草案后重开仍可继续编辑，用户可继续编辑分镜。再次生成时确认当次选中的镜头、内容版本与模型。
3. **接工作台。** 在会话 A 搜索墨墨，选一张参考图保存到项目分镜，再从侧栏新建会话 B。验收时检查 B 的首次模型请求，里面应无 A 的消息、摘要、工具结果或工作台草案。在 B 说「用刚才的第三张」，Agent 应请用户指明确切素材。在 B 说「从我的素材库找墨墨-招手」，应观察到新的资产查询及返回的资产 ID。切回 A 能看到原候选顺序，重开项目仍能看到分镜保存的参考图。

单条原文超出输入预算时，在当前对话中紧跟该消息显示系统提示「这次提交的原文太长，请拆成几段提交」。输入框保留原文，方便用户在同一会话编辑后再发。提示属于本次提交的状态，历史装配只使用已保存的会话消息。

第 11 课不额外引入图像生成供应商，先使用已有参考图或文生视频能力。API 权限或预算未就绪时，可以明确标注模拟任务完成接口学习；真实接入验收保持待完成，不用模拟结果宣称接通。

### 第十一至十二课：记录每次生成的输入、用量和费用

第十一课随首个视频 Gateway 设计 MySQL 生成记录。每次实际提交保存发送给供应商的最终提示词、参考素材 ID、生成参数、供应商和模型，以及本地生成记录与供应商任务 ID 的关联。任务结束后补记状态、用量及其单位、报价和可核实的实际费用及币种。失败和重做也有各自的记录。轮询同一个任务时更新这次记录，项目统计只计入一次。生图接入时复用这套记录方式，具体字段随供应商响应和账单数据确定。

每个成功的视频卡片根据对应的单次生成记录展示费用。已有结算数据时标为「实际费用」，否则标为「估算费用」。生成前的确认界面只展示待确认的版本、镜头范围和生成参数。

第十二课增加第二家供应商后，验证能按项目或模型查到每次生成记录并汇总费用。用量带原始单位，费用按币种汇总。供应商只返回用量、暂未确认应付金额时，保留估算并标记结算状态。

视频协议使用“提交 → 查询 → 获取结果”，文本协议使用消息与响应。按项目需要复用基础请求处理，但不将视频任务强行封装成聊天请求。

Gateway 的具体设计以[路由讨论记录](./gateway-routing-discussion.md)为依据；能力匹配只代表请求可提交，成片质量另行检查。第一版不以无实测依据的“质量分”路由。

Embedding 服务或本地模型到第 15 课根据可用资源确认，不假设已选的文本 API 自带 Embedding。检索先在内存处理小数据，不先引入外部向量数据库。

### PPT 主题大纲与时间分配

**《一句话开拍，Agent 在幕后忙什么？》**

用短剧工坊拆解 Agent Loop、上下文管理与 Harness。

用「从素材库找墨墨，做一段夜晚窗台的短剧」贯穿全场。观众先看到需求、分镜和样片，再跟着同一次创作看模型怎样用工具、如何接上长对话，以及付费动作怎样由程序把关。

PPT 只安排一张目录页，列出下面六个章节标题。时间分配、讲解深度和演示内容留在讲解大纲里。

| 主题                               |    时间 | 讲解深度                           | 展示内容                                                                                                                                                                                        |
| ---------------------------------- | ------: | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 短剧 Agent 的业务流程与系统架构 |  5 分钟 | 开场演示                           | 快速展示一句需求、可编辑分镜和一段样片，用一张架构图定位模型、Harness、业务工具和外部供应商。                                                                                                   |

### PPT 里的 ReAct 与 Orchestrator

用第 5 课已验证的「搜索墨墨」做一页流程图。第一次模型调用提出 `search_user_assets`，Harness 执行搜索并带回工具结果，第二次模型调用根据候选回答。展示工具请求、工具结果和最终回答这些可观察记录。

- **ReAct** 讲模型怎样根据观察结果决定下一步，用现有循环展示「提出动作 → 观察结果 → 再决定」的模式。 [ReAct 原始论文](https://arxiv.org/abs/2210.03629)
- **Orchestrator** 讲程序怎样组织和控制过程。用 `AgentService` 指出调用模型、派发工具、追加结果、结束循环的位置，再连到第 7 课的上下文预算。第 8 课用素材搜索演示步数上限。生成确认与幂等使用第 10–11 课真实分镜和任务的验收记录。 [Agent Loop 实现](../src/harness/agent/agent.service.ts)
