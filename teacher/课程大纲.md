# 一句话开拍：短剧工坊学习与开发课程大纲

编写日期：2026-11-02。状态：原课程安排及后续调整；前三课核心链路已运行，第四课准备中。最新技术方案以[项目目标与范围](./project-goals-and-scope.md)为准。

分享主题：**《一句话开拍，Agent 在幕后忙什么？》**  
副标题：用短剧工坊拆解 Agent Loop、上下文管理与 Harness

## 1. 学完后交付什么

做一个规模受控的短剧工坊：输入剧情需求 → 展示可修改的剧本和分镜草案 → 观察 Agent 调用工具 → 确认视频模型与费用 → 审批生成 → 查看片段与执行记录。

初期以三镜、约 15 秒片段作为演示案例，镜头数可由用户指定或由 Agent 建议，不写死在业务规则中；按预算再扩展到 30–60 秒小故事。完整拼接导出与逐镜预览分开验收，不把只有片段预览描述为已经生成完整成片。

- 文本主线：DeepSeek，具体型号与 API 协议在接入时确认。
- 视频候选：Seedance 2.5、Grok Imagine Video 1.5，先接通一家，再适配另一家。
- 学习重点：Agent 与 Harness 的关系、Loop、提示词装配、上下文管理与压缩、模型决策、工具执行。
- 全部覆盖：原截图 14 项，各有解释、代码或独立小实验及验证依据。
- 后期扩展：评测 Agent 和基于质量记录的模型路由，分享时介绍思路，当前不要求实现。

## 2. 每一课怎样进行

一课可以拆成多次小步骤，不要求一次对话完成。

| 环节 | 助手做什么 | 你做什么 | 进入下一环节的依据 |
|------|------------|----------|------------------|
| 文档讲解 | 先写本课目标、概念、短剧例子、数据流与边界 | 阅读并提出疑问 | 能理解本课要解决的问题 |
| 理解检查 | 追问关键分工，按疑问补充解释 | 用自己的话复述或预测行为 | 能解释关键过程，不要求背术语 |
| 小步编写 | 只给当前步骤的文件、任务与预期结果 | 亲手建文件、写代码和运行 | 当前小步骤有可检查的代码与输出 |
| 针对性验证 | 读取实际代码，检查成功与必要失败路径 | 修改问题并再次运行 | 实际行为符合本课目标 |
| 分享沉淀 | 协助提炼口头解释、证据与一个边界案例 | 用两三句话向同事解释 | 能讲清为什么这样做 |

实现代码、配置与依赖安装由你操作；未经明确要求，助手只编写教学文档、讲解和检查，不提前代写后续功能。

普通入口和文案不专门堆测试；工具权限、预算、循环停止、路由和重复提交等行为需要针对性验证。真实付费接口的验证单独安排，不在普通回归中反复调用。

## 3. 开发节奏与阶段成果

本大纲建议预留约 **35–50 小时**，是包含阅读、编写、调试和复述的学习投入估计，不是交付承诺。实际随理解速度、API 开通情况与排错调整。

若按三周安排，平均每周约 12–17 小时；若压到两周，需要平均每周约 18–25 小时。原分享时间是 2026-10-29 提到的“2–3 周后”，具体日期待定，因此以下使用学习阶段，不假设从今天起仍有完整三周。

| 阶段 | 课程 | 阶段成果 |
|------|------|----------|
| A：看懂模型如何行动 | 01–05 | 终端里运行真实的模型与工具反馈循环 |
| B：把循环管起来 | 06–08 | 上下文选择、压缩、审批、预算和停止条件可解释、可验证 |
| C：形成可演示工坊 | 09–12 | 页面看到剧本、分镜与过程，视频任务和模型路由接入 |
| D：补齐知识点实验 | 13–18 | Skill、MCP、RAG、Memory、回归与框架对照各有小实验 |
| E：整理技术分享 | 19 | 45–60 分钟分享材料、演示和备用说明 |

时间紧时优先减少页面打磨、成片时长与付费生成次数；保留关键概念和验证，不把未完成实验写成已实现功能。

## 4. 课程安排：先看懂一轮调用

以下路径都是未来按课程创建的目标路径，当前不预先建立目录。课程编号是学习顺序，与截图中的 14 项编号分开。

| 课次 | 学习问题 | 本课亲手开发的内容与目录 | 验证与过关标准 |
|------|----------|--------------------------|----------------|
| 01 模型、Agent 与 Harness | 一次用户提问为什么可以包含多次模型调用？谁负责执行？ | `src/main.ts`：保存并打印用户需求；理解后再创建基础 `package.json` 等运行配置 | 能运行入口；知道此时模型调用为 0 次；能复述模型、工具与运行时的分工 |
| 02 第一次真实模型调用 | 从本地字符串到模型响应，经过哪些步骤？ | `src/gateway/text/deepseek.ts`：请求与响应；`src/gateway/text/types.ts`：最小消息与结果类型；环境变量示例 | 拿到真实回复；能识别请求失败；密钥配置与业务输入分开；说出这次模型调用次数 |
| 03 提示词与结构化剧本 | 规则放在哪？写了 Prompt 为什么还需要校验？ | `src/prompts/`：创作规则；`src/domain/`：简化剧本、分镜类型及运行时校验 | 输出梗概、场景、动作与对白，以及可编辑分镜草案；缺字段或不符合本次指定镜头数能被程序识别 |
| 04 工具定义与执行 | 模型看到工具说明以后，实际是谁运行函数？ | `src/tools/registry.ts`、`src/tools/search-user-assets.ts`：先做当前用户素材库的关键词搜索工具，不继续扩展逐字段校验 | 观察真实工具请求、必要参数检查与执行结果；不存在的工具、错误参数不会被直接执行 |
| 05 手写 Agent Loop | 工具结果怎样回到模型？模型何时继续、何时结束？ | `src/harness/loop.ts`、`src/harness/state.ts`：完整消息往返与循环；保留模型发起调用的记录 | 同一任务出现至少一次工具反馈后的模型调用；能画出调用顺序，验证步数上限；不强迫所有任务都调用工具 |

第 05 课开始记录少量运行事件，便于观察；到第 09 课再统一为 Trace 和前端事件，避免把“日志晚点做”理解为之前完全看不见执行过程。

## 5. 课程安排：上下文与运行控制

| 课次 | 学习问题 | 本课亲手开发的内容与目录 | 验证与过关标准 |
|------|----------|--------------------------|----------------|
| 06 提示词装配与上下文管理 | 每轮模型到底看到了什么？哪些是规则，哪些是资料？ | `src/harness/context.ts`、`src/prompts/`：组合任务、规则、最近历史和工具结果；保留完整原始记录 | 展示每轮输入的组成；最新用户修改能影响下一步；区分正常装配与不可信资料中的 Prompt Injection |
| 07 上下文压缩 | 历史变长时保留什么、移出什么，损失怎么验证？ | `src/harness/compaction.ts`：先控制冗长工具结果，再摘要较早的历史；长内容保存到产物文件 | 对比压缩前后长度与下一轮结果；保留最新需求、待处理事项和工具调用配对；说明摘要也可能丢信息 |
| 08 Harness：状态、审批与预算 | 谁决定允许执行？模型想继续，程序能不能停止？ | `src/harness/approval.ts`、`budget.ts`、`errors.ts`，扩展状态与循环 | 批准后执行、拒绝后不执行；达到步骤或费用限制能停止；区分上下文 token 预算与生成费用预算 |

上下文摘要可能额外调用模型，应计入 Trace 和费用。模型请求中使用的上下文与完整历史存档分开管理；不通过修改模型参数实现“记住”。

本阶段顺带解释编排：普通程序按依赖组织步骤，模型在允许范围内选择动作。先写单 Agent 的流程；LLM 动态拆任务、协调 workers 的模式在框架对照时再解释，不提前引入多 Agent 实现。

## 6. 课程安排：从终端走到短剧工坊

| 课次 | 学习问题 | 本课亲手开发的内容与目录 | 验证与过关标准 |
|------|----------|--------------------------|----------------|
| 09 HTTP、SSE 与 Trace | 模型输出流、业务事件与调试记录有什么区别？ | `src/server/`：HTTP 入口和 SSE；`src/protocol/`：事件契约；`src/harness/trace.ts`：关联运行记录 | 页面或请求客户端逐步收到文本、分镜、审批和终态；能区分失败、取消与成功；理解网络分块不等于事件边界 |
| 10 前端剧本与分镜工作台 | 用户怎样看见产物、修改要求和控制生成？ | `web/`：拟采用 React + TypeScript，具体工具在本课确认；需求输入、剧本/分镜视图、审批与运行记录 | 能查看剧本与分镜，提交某镜修改并看到结果；页面状态由服务端事件驱动；模型调用仍在服务端 |
| 11 视频工具与首个供应商 | 创建视频任务为什么不等于拿到视频？ | `src/gateway/video/`：统一任务类型与第一家适配器；`src/tools/generate-video.ts`；`src/media/`：片段与后续拼接；`assets/references/`：自有参考素材 | 经审批提交真实任务，查询到成功或失败；能播放生成片段；单独验证拼接后的完整文件，未拼接时明确标为逐镜预览 |
| 12 双供应商 Gateway 与路由 | 用户固定选型与自动选型如何共存？ | 增加第二家视频适配器；`src/gateway/catalog.ts`、`capabilities.ts`、`pricing.ts`、`route.ts` | 先手动切换，再验证能力、预算和成本路由；展示选择原因；超时不重复付费生成；两家分别有接入依据 |

第 11 课不额外引入图像生成供应商，先使用已有参考图或文生视频能力。API 权限或预算未就绪时，可以明确标注模拟任务完成接口学习；真实接入验收保持待完成，不用模拟结果宣称接通。

视频协议使用“提交 → 查询 → 获取结果”，文本协议使用消息与响应。按项目需要复用基础请求处理，但不将视频任务强行封装成聊天请求。

Gateway 的具体设计以[路由讨论记录](./gateway-routing-discussion.md)为依据；能力匹配只代表请求可提交，成片质量另行检查。第一版不以无实测依据的“质量分”路由。

| 课次 | 学习问题 | 本课亲手开发的内容与目录 | 验证与过关标准 |

| 13 业务 Skill | 为什么一份创作指令和一个执行工具不是同一回事？ | `skills/`：反转、喜剧两套指令与模板；`src/skills/`：发现和按需加载；独立入口放在 `labs/skills/` | 展示加载前后的上下文变化；解释 Skill 提供方法与资源、Tool 提供执行能力；不只把重命名函数称为 Skill |

| 15 RAG 与 Embedding | 怎样让模型参考团队规范？检索与生成怎样衔接？ | `knowledge/`：少量自有分镜规范；`src/retrieval/`：切块、Embedding、内存检索与来源；`labs/rag/` | 查询返回相关片段，并把片段带入生成；展示来源与检索失误；不将固定素材返回当成向量检索 |
| 16 Memory | 单次任务、同一会话、跨任务偏好怎样分开？ | `src/memory/`：会话与偏好读写；`labs/memory/`：对照入口；运行数据放 `data/` | 新任务能加载明确保存的偏好；不同用户隔离；能修改和清除；解释记忆存储与上下文加载的区别 |
| 17 拦截与回归验证 | 代码改动后怎样确认旧行为还可靠？ | `tests/`：确定性回归；`fixtures/`：固定需求、错误和样例结果；真实模型质量评估单独入口 | 不付视频费用也能验证拒绝不执行、预算终止、工具错误、路由与任务超时；真实模型按字段和业务规则评估，不要求原文逐字相同 |
| 18 LangChain、LangGraph 与框架对照 | 框架替代了哪些代码？Loop、图编排和 Harness 怎么对应？ | `labs/frameworks/`：独立小例子，对照模型/工具抽象与 state、node、edge、interrupt | 能将手写实现映射到框架职责，并解释固定编排与动态决策；保留主工程，避免为了比较重写整个项目 |

Embedding 服务或本地模型到第 15 课根据可用资源确认，不假设已选的文本 API 自带 Embedding。检索先在内存处理小数据，不先引入外部向量数据库。

Skill、MCP、RAG、Memory、框架实验各有可单独运行的小入口，便于分享展示。确认理解后再选择是否接入主线，不要求一次运行调用全部能力。

### 第 13 课参考：AI Short Drama Workflow

2026-11-05 用户确认，将 [AI Short Drama Workflow](https://github.com/tianqing-Y/ai-short-drama-workflow) 作为后续 Skill 课程的参考或内部集成候选。当前只记录，不安装、不接入，也不以其工作流替代手写 Agent Loop 的学习。

本课重点观察其 `SKILL.md` 与 `references/` 的分工、按创作阶段选择指令、按需加载参考资料，以及分镜和图片/视频提示词的组织方式。

到第 13 课时，先核查所选版本的许可证与署名要求、引用文件、工具依赖及与本项目数据协议的兼容性，再选择借鉴后自行编写、裁剪适配，或直接集成。固定参考版本并保留来源，不假设公开仓库天然允许任意复用。

若集成，Skill 提供创作方法和参考资源；发现、选择和上下文加载由 Harness 实现，实际模型与视频请求仍经过本项目 Gateway、工具和审批控制。外部 Skill 的默认规则不覆盖用户已确认的分镜数量与生成范围。

## 8. 第 19 课：把验证过的内容变成分享

| 产物 | 内容 | 完成依据 |
|------|------|----------|
| 课程笔记 | `teacher/` 中随学习形成的说明和问答 | 每课能用自己的话复述，有对应运行证据 |
| 演示脚本 | 到本课再创建 `scripts/demo-script.md` | 一条主路径和一条拒绝/失败路径能重复演示 |
| 分享材料 | 到本课再创建 `presentation/`，整理讲点、素材与后续 PPT | 与实际代码状态对齐，所有未实现内容明确标为扩展 |

建议先按约 50 分钟内容、10 分钟交流准备；若只有 45 分钟，减少现场操作和代码展开，将独立实验放入附录，保留每个知识点的解释与入口。

叙事主线：从一次提问出发 → 模型怎样提出动作 → Harness 怎样执行和反馈 → 上下文怎样持续整理 → 用户怎样观察和控制 → 不同模型怎样接入与选择 → 怎样验证与扩展。

评测 Agent 留作扩展页：说明输入什么产物、怎样使用规则检查与视听评测、如何输出证据，以及未来怎样反馈给 Gateway；不作为当前成片质量已经自动保证的依据。
