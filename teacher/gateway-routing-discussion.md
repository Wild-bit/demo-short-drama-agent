# Gateway 模型路由：讨论记录

记录日期：2026-11-02。状态：提前讨论、待实现；不代表已经完成对应课程、接通 API 或验证模型效果。

## 已确认的范围

- 文本主线使用 DeepSeek，承担剧本、分镜与工具决策。
- 视频生成将 Seedance 2.5、Grok Imagine Video 1.5 作为可能同时使用的候选；具体型号、接口、账户权限和费用在接入时核实。
- 第一阶段先让用户明确选择视频模型，后续增加按规则自动路由。
- 评测 Agent 属于后期扩展，分享时可介绍扩展方向，不作为当前主线必须实现的功能。
- 当前继续按“文档先行 → 理解 → 用户亲手编写 → 验证”学习，不提前实现 Gateway。

下文作为本次讨论的设计基线；具体字段和参数到对应课程时再确定。

## 职责分工

| 角色 | 职责 |
|------|------|
| 用户 | 明确选择模型或自动模式，设定预算、输出规格及允许的备用模型 |
| DeepSeek | 形成创作内容和工具调用请求，可以提出生成建议 |
| Harness | 保存用户约束与任务状态，组织审批、预算和工具执行，处理继续与结束 |
| Gateway | 执行路由规则、检查模型能力、估算费用，并适配各厂商接口与返回值 |

这里的 Gateway 是项目内部适配与路由模块，可以先做成普通模块，无需独立部署。文本请求与视频任务采用各自合适的操作接口，不强行将视频生成塞进聊天接口。

模型提出的建议仍受用户选择、能力要求和预算约束。自动路由先用普通程序执行明确规则，不额外调用一个 LLM 猜测品牌。

## 两种选择模式

**手动模式**：固定使用用户选择的具体型号。若能力不符合或超预算，展示原因和可选调整，等待用户修改要求；不静默切换厂商或拆分镜头。

**自动模式**：按“可用范围 → 能力过滤 → 预算过滤 → 偏好排序”确定候选。

界面可以展示 Seedance、Grok、自动选择三个选项。默认选项应显示为具体型号，不能把固定 Seedance 的行为命名为自动选择。

## 自动路由规则

1. **筛选可用范围**：用户允许的供应商与型号、已配置的接口，以及经核实的账户调用权限。只有 Key 配置存在，不足以证明型号可用。
2. **过滤能力要求**：检查生成方式、时长、分辨率、比例、参考素材、音频需求和参数组合限制。
3. **过滤预算**：估算本次任务费用，与剩余可用预算比较。没有可比报价或关键能力尚未验证的候选，标明原因，不直接认定合格。
4. **排序候选**：第一版自动模式建议采用“满足条件后，预计费用较低者优先”。成本相同或估算差异不足以区分时，采用配置的稳定优先级，并说明理由。
5. **没有候选**：返回具体排除原因，提示用户调整要求、预算或允许范围；不自动突破限制。

预算按本次任务范围计算，包括计划生成的镜头与版本数、已经发生的费用及运行中任务的预算占用。同一任务的并行镜头共享预算，不能各自把同一笔剩余额度用完。

估算费用与实际结算分别记录。预算预留及估算余量的具体策略，待接入真实报价与任务接口后确定。

## “满足要求”具体指什么

此处仅表示候选接口能够接收这次请求，不保证输出一定达到创作标准。

| 请求检查 | 依据 |
|----------|------|
| 生成方式与输入素材 | 官方接口说明、接入验证结果 |
| 时长、分辨率和宽高比 | 该具体型号与任务模式的限制 |
| 素材数量、大小和格式 | 官方限制及实际请求校验 |
| 能力组合 | 同时使用这些参数是否受限，不能由单项支持推断组合支持 |
| 账户可用性 | 接口开通情况与已核实的权限 |

能力清单保留来源、核查时间和验证状态；没有核实的内容标为“未验证”。接入小样例通过，只证明该样例规格可调用。

人物一致性、中文台词、口型、表演和运镜遵循属于产物质量，需要看实际结果。尚无项目实测记录时，不启用按品牌印象排序的“质量优先”。

## 一次任务中的选择与审批

- 整部短剧默认沿用同一视频模型，便于观察人物和画风连续性；这只是初始设计策略，不是效果保证。
- 用户可以对某一镜明确重新选择模型；自动路由优先在整次任务规划时完成，不为每一镜随意换厂商。
- 提交前展示最终型号、生成规格、计划版本数、费用估算与选择理由，由 Harness 按既定规则处理审批。
- 审批后固定本次提交的供应商、型号和参数。若更换模型、扩大生成范围或提高费用超出已批准范围，应重新确认。

## Gateway 统一什么

统一模型能力查询、费用估算、任务提交、状态查询和结果获取；保留厂商特有能力的扩展入口，不能用统一接口假装两家能力完全相同。

对上返回项目任务标识、实际供应商与型号、厂商任务 ID、统一状态、结果地址和错误信息。费用记录区分估算与实际用量，并保留报价依据。

Harness 保存任务状态和预算，Gateway 负责厂商适配。先用最小实现学懂职责，再按实际需求增加存储和部署能力。

## 超时、失败与切换

- 等待超时不等于厂商生成失败。先凭原任务 ID 查询，不能直接向另一家再次付费生成。
- 对提交结果不明确的任务，先核对原任务状态和重复提交风险；不盲目重新提交。
- 明确失败后，才根据用户允许的备用模型、已批准范围和剩余预算决定是否重试或切换。
- 审批拒绝或用户取消不能触发自动换模型重试。
- 对已提交任务的取消和计费处理，以厂商实际能力和返回状态为准，不承诺一定可撤销或退款。

## 可观察性与验证目标

Trace 记录请求规格、手动或自动模式、候选及排除原因、选择依据、实际型号、估算费用、审批、任务状态、切换过程及实际用量。

后续编写到此处时，应验证以下场景：

| 场景 | 预期行为 |
|------|----------|
| 两家均符合能力与预算 | 按成本规则选择并给出理由 |
| 只有一家符合 | 选择该候选并说明其他候选的排除原因 |
| 无候选、超预算或能力未验证 | 返回具体原因，不强行提交 |
| 用户固定型号但请求不兼容 | 提示调整，不静默切换 |
| 原任务超时但仍运行 | 继续核对原任务，不重复生成 |
| 并行镜头共享预算 | 费用占用合并计算，避免重复分配额度 |
| 审批后参数或型号改变 | 检查是否超出已批准范围 |

## 后期扩展：评测 Agent

分享时可以介绍“生成 → 评测 → 修改”的方向，当前主线不实现该 Agent。

先由普通程序检查播放、时长、分辨率和音轨，再由具有相应视听能力的评测模型检查内容。报告应包含结论、问题位置、证据和修改建议，并允许“无法判断”。

未来评测 Agent 可以按需要调用抽帧、转写和补查工具。是否再次生成仍由 Harness 结合审批、预算和最大轮数控制。

当积累足够实测样本后，才考虑将分场景通过率、耗时和可用片段成本用于 Gateway 的质量排序；这一扩展不阻塞当前的能力与预算路由。
