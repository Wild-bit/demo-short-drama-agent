# 短剧工坊：项目目标、范围与架构约定

更新日期：2026-11-05。作为后续课程与实现的统一依据；早期文档与本约定冲突时，以本约定为准。本文描述目标和阶段安排，不代表功能已经实现。

## 1. 整体目标

以短剧工坊为真实业务载体，由用户亲手构建一个运行链路完整、可以持续演进的 Agent 应用，理解原定 14 项知识点，并据此完成技术分享与 PPT。

分享主题：《一句话开拍，Agent 在幕后忙什么？》；副标题：用短剧工坊拆解 Agent Loop、上下文管理与 Harness。

技术分享是阶段性交付。项目按用户、项目和资产归属组织业务，不因演示阶段暂缓登录和接口鉴权，就定位为单用户产品。

学习重点是模型决策、工具执行、Loop、提示词装配、上下文管理与压缩、Harness 控制。数据库、Web 服务和存储支撑真实业务，按需要教学，不喧宾夺主。

## 2. 产品主线

1. 用户上传或选择已有素材，形成个人资产库。
2. 创建、打开短剧项目，输入创意、剧本或已有分镜。
3. Agent 按需搜索素材，生成剧本与分镜草案。
4. 用户查看草案，通过对话或直接编辑修改、增删镜头；程序保存草案，项目列表可再次打开。
5. 用户确认分镜版本，选择视频模型，查看费用估算和本次生成范围。
6. 确认后执行生成，展示逐镜状态、失败信息和执行记录。
7. 将生成文件存入 COS，在 MySQL 登记资产，关联项目和分镜，支持预览与再次使用。

镜头数由用户指定或由 Agent 根据剧情建议，三个镜头只是教学样例。草案保存、列表和常规编辑属于产品流程，不强行要求模型决定是否执行。

生成片段与完整成片分开验收；只有片段预览时不声称已完成成片拼接。拼接导出属于目标能力，具体完成状态以运行结果为准。

## 3. 数据关系

| 对象 | 责任与关系 |
|------|------------|
| 用户 | 资产与项目的归属主体 |
| 资产 | 名称、类型、描述、标签、所属用户、COS 对象引用等；既包含上传素材，也包含生成产物 |
| 项目 | 组织剧本、分镜、素材引用、会话和运行任务 |
| 剧本与分镜 | 可编辑的创作内容；分镜可引用所选资产 ID |
| 会话与消息 | 保存用户、模型、工具交互；历史存档与每次发送的上下文分开 |
| 执行任务与审批 | 保存任务状态、确认版本、模型、参数、费用范围及供应商任务标识 |
| 执行记录 | 关联模型调用、工具、错误和耗时，为 Trace 提供依据 |

项目和分镜引用资产，不要求为每次引用复制文件。稳定记录 ID 与显示顺序应分开：现有 `Shot.id` 暂为草案内序号，进入持久化编辑时补充稳定标识，避免镜头重排导致任务关联错位。

确认与审批在服务端保存；已确认内容或费用范围发生变化时，重新确认受影响的生成任务。具体表结构随课程逐步设计，不一次建全表。

## 4. 已确认技术栈与职责

| 组件 | 职责 |
|------|------|
| NestJS | HTTP 服务、模块组织、业务服务、依赖注入，后续承载 SSE |
| TypeORM | MySQL 连接、实体映射、数据访问和迁移 |
| MySQL（Docker Compose） | 保存业务记录、用户归属、任务状态和文件引用 |
| 腾讯云 COS | 保存上传素材、生成图片、视频片段及成片文件 |
| DeepSeek | 当前文本生成与工具决策模型，已完成真实请求 |
| 视频 Gateway | 适配候选供应商、统一任务提交与查询、支持模型选择规则 |
| Web 工作台 | 对话、项目列表、素材库、分镜编辑、确认、预览和执行记录；具体前端工具到对应课确定 |

不采用本地 JSON 清单模拟数据库作为主方案，也不要求本地目录承担长期素材和视频存储。

COS 保存文件本体，MySQL 保存对象 Key 等稳定引用。临时访问地址按访问需要生成，不把会过期的签名 URL 当作永久文件身份。生成任务完成后获取供应商产物并存入 COS，不只依赖供应商临时链接。

## 5. 运行架构

Web 或终端入口 → 业务服务 / Harness → Gateway 请求模型。

模型提出工具调用 → Harness 查找与执行工具 → 资产服务查询 MySQL → 返回真实结果 → Harness 按规则决定继续或结束。

资产 HTTP 接口与 Agent 工具复用同一资产服务，工具不通过 HTTP 调用自己的服务绕一圈。资产服务按需调用 COS 存储适配器。

Harness 管理上下文、状态、工具执行、权限边界、审批、预算和停止条件；NestJS 提供应用组织机制，不替代这些 Agent 运行逻辑。普通数据库操作或固定上传流程不必每一步由模型决策。

现有 `request`、`gateway`、`prompts`、`domain` 作为可复用代码保留；逐步接入 NestJS，不创建新项目覆盖现有源码。模块目录在实际搭建前单独讲解。

## 6. 演示阶段的取舍

暂不实现登录注册、JWT 或接口鉴权、复杂角色权限、管理后台和多人实时协作。这不删除用户与资产的归属关系。

演示请求可以由服务端配置固定演示用户上下文；后续认证接入时替换身份来源。模型工具参数不提供任意用户 ID，不把前端随意传值当作已验证身份。该阶段不声称已实现认证或多用户安全隔离。

Agent 的预算、付费生成确认、任务停止和重复提交控制仍按课程实现；这些与是否有登录接口是不同问题。

界面先使用对话区、项目与素材列表、可编辑分镜列表，不引入无限画布、复杂时间线、完整历史对比或协同编辑。

## 7. 分享前范围与扩展

分享前主线目标：项目和草案持久化、真实资产查询、模型与工具反馈循环、上下文管理、Web/SSE/Trace、确认后的视频任务执行和 COS 产物预览。

原 14 项保持覆盖：Skill、MCP、RAG/Embedding、Memory、回归与框架对照按独立实验逐步补充，不要求每次业务运行调用全部能力。AI Short Drama Workflow 留作 Skill 课程参考或集成候选。

评测 Agent、基于评测质量的模型路由、无限画布、复杂剪辑、完整版本历史、登录与细粒度权限等留作扩展。Gateway 先手动及默认选择，再加明确的能力和预算规则，不把接口支持等同于质量保证。

## 8. 调整后的课程节奏

1. 已完成前三课主线：真实文本请求、公共 HTTP 封装、提示词与 JSON 模式；工具反馈循环尚未实现。
2. 第四课前段补基础设施小节：NestJS 最小启动 → TypeORM/MySQL 连接 → 资产记录与真实样本 → COS 引用和访问验证 → 资产查询服务。
3. 第四课后段：`search_user_assets` 声明、注册、模型请求和真实数据库查询。
4. 第五课：工具结果回传与 Agent Loop；终端可以继续作为观察入口。
5. 后续按大纲增加上下文管理、控制、HTTP/SSE 和 Web 工作台。NestJS 已提前引入，届时扩展现有服务，不重复搭建。

基础设施扩展增加了配置、连接、持久化和联调工作，原 35–50 小时估算不再未经核算直接沿用。待 MySQL、COS 与 NestJS 最小链路验证后，根据剩余分享时间重新估算；不提前承诺全部功能在原时间内完成。

## 9. 协作与验证

文档先行 → 理解讨论 → 用户亲手写当前一小步 → 助手检查代码与运行结果。明确授权时可代写指定内容，不视为后续代码均可代写。

每阶段分别记录“已设计、已编写、已验证”。只对声明成功的功能保留必要证据，不因一段模型回答就声称动作已经执行。

下一步先准备 NestJS 接入说明，核查现有构建与运行方式；随后指导用户逐步配置。MySQL 可用环境、COS Region/Bucket 与凭证加载方式在接入对应组件时确认，密钥不写进文档。

## 第四课基础设施补充

MySQL 使用 Docker Compose，本机只需 Docker 引擎，不安装 MySQL 服务。第一阶段准备连接与独立数据库健康检查，之后再做资产实体和迁移。工具主线为 `search_user_assets`，后续加入 `generate_image_asset` 补齐缺少的角色、场景或道具参考图；Web 可从素材库、分镜参考素材和对话进入，复用资产生成服务。

## 本地运行方式更新

NestJS API 和 MySQL 均使用 Docker Compose，宿主机 API 端口 3100，容器内 API 端口 3000，数据库内部访问 `mysql:3306`。默认开发镜像挂载源码，容器内安装依赖、编译与重启。当前验证限制和命令见[容器运行说明](./04c-containerized-api.md)。
