# 短剧工坊：项目目标、范围与架构约定

更新日期：2026-11-18。作为后续课程与实现的统一依据；早期文档与本约定冲突时，以本约定为准。本文描述目标和阶段安排，不代表功能已经实现。

日常修改时直接遵守的协作和架构规则已提炼到 [AGENTS.md](../AGENTS.md)。本文保留项目目标、课程范围和各阶段的设计背景。

## 1. 整体目标

以短剧工坊为真实业务载体，由用户亲手构建一个运行链路完整、可以持续演进的 Agent 应用，理解原定 14 项知识点，并据此完成技术分享与 PPT。

分享主题：《一句话开拍，Agent 在幕后忙什么？》；副标题：用短剧工坊拆解 Agent Loop、上下文管理与 Harness。

技术分享是阶段性交付。第六课建立用户与会话归属，第十课引入短剧项目，组织可跨会话使用的创作成果。

学习重点是模型决策、工具执行、Loop、提示词装配、上下文管理与压缩、Harness 控制。数据库、Web 服务和存储支撑真实业务，按需要教学，不喧宾夺主。

## 2. 产品主线

1. 用户上传或选择已有素材，形成个人资产库。
2. 创建、打开短剧项目，输入创意、剧本或已有分镜。
3. Agent 按需搜索素材，生成剧本与分镜草案。
4. 用户查看草案，通过对话或直接编辑修改、增删镜头；程序保存草案，项目列表可再次打开。
5. 用户确认本次生成的分镜版本、镜头范围和模型。
6. 确认后执行生成，展示逐镜状态、失败信息和执行记录。
7. 将生成文件存入 COS，在 MySQL 登记资产并关联项目和分镜。用户可预览、再次使用，并在每个成功的视频卡片查看本次生成的实际费用或估算费用。

镜头数由用户指定或由 Agent 根据剧情建议，三个镜头只是教学样例。草案保存、列表和常规编辑属于产品流程，不强行要求模型决定是否执行。

生成片段与完整成片分开验收；只有片段预览时不声称已完成成片拼接。拼接导出属于目标能力，具体完成状态以运行结果为准。

## 3. 数据关系

| 对象 | 责任与关系 |
|------|------------|
| 用户 | 资产与项目的归属主体 |
| 资产 | 名称、类型、描述、标签、所属用户、COS 对象引用等；既包含上传素材，也包含生成产物 |
| 项目 | 组织剧本、分镜、素材引用、会话和运行任务 |
| 剧本与分镜 | 可编辑的创作内容；分镜可引用所选资产 ID |
| 会话与消息 | 每个会话归属一个用户。第十课起项目可关联多个会话。每个新会话从空历史开始，消息、工具调用与结果、压缩摘要都只按本会话读取。此前创建的独立会话继续可用 |
| 执行任务与审批 | 保存任务状态、确认版本、模型、参数和供应商任务标识 |
| 生成记录 | 为每次生图或生视频保存实际提交的提示词、参考素材引用、模型、用量和费用，供项目回查与汇总。随第十一至十二课设计 |
| 执行记录 | 关联模型调用、工具、错误和耗时，为 Trace 提供依据 |

项目和分镜引用资产，不要求为每次引用复制文件。稳定记录 ID 与显示顺序应分开：现有 `Shot.id` 暂为草案内序号，进入持久化编辑时补充稳定标识，避免镜头重排导致任务关联错位。

工作台打开项目时从项目记录恢复已保存的剧本和分镜。切换到新会话时，工作台正在展示的草案也不会自动进入模型输入。Agent 要复用素材、角色或生成的视频时，通过工具查询当前用户有权访问的资产，工具结果进入本轮上下文。视频资产应能查到生成时对应的镜头脚本版本和实际提交的提示词，之后编辑分镜仍可追溯到当时的输入。

后续课程中，同一用户的多个会话可按权限使用已启用的 Skill 和 MCP 工具。每次会话按需加载创作指令、调用工具。Memory 允许新会话读取该用户明确保存的偏好，例如默认画幅；会话摘要仍归原会话。

确认与审批在服务端保存。执行时从用户确认的分镜版本读取镜头内容。提示词随分镜编辑与确认，生成内容、范围或模型变化时，重新确认受影响的任务。费用随任务记录，用户在成功产物卡片查看。供应商的账户和调用限制按实际接口规则处理。具体表结构随课程逐步设计。

## 4. 已确认技术栈与职责

| 组件 | 职责 |
|------|------|
| NestJS | HTTP 服务、模块组织、业务服务、依赖注入，后续承载 SSE |
| TypeORM | MySQL 连接、实体映射、数据访问和迁移 |
| MySQL（Docker Compose） | 保存业务记录、用户归属、任务状态和文件引用 |
| 腾讯云 COS | 保存上传素材、生成图片、视频片段及成片文件 |
| DeepSeek | 当前文本生成与工具决策模型，已完成真实请求 |
| 视频 Gateway | 适配候选供应商、统一任务提交与查询、支持模型选择规则 |
| Web 工作台 | 对话、项目列表、素材库、分镜编辑、确认、预览和执行记录；具体前端工具到对应课确定 |

不采用本地 JSON 清单模拟数据库作为主方案，也不要求本地目录承担长期素材和视频存储。

COS 保存文件本体，MySQL 保存对象 Key 等稳定引用。临时访问地址按访问需要生成，不把会过期的签名 URL 当作永久文件身份。生成任务完成后获取供应商产物并存入 COS，不只依赖供应商临时链接。

## 5. 运行架构

Web 或终端入口 → 业务服务 / Harness → Gateway 请求模型。

模型提出工具调用 → Harness 查找与执行工具 → 资产服务查询 MySQL → 返回真实结果 → Harness 按规则决定继续或结束。

资产 HTTP 接口与 Agent 工具复用同一资产服务，工具不通过 HTTP 调用自己的服务绕一圈。资产服务按需调用 COS 存储适配器。

Harness 管理上下文、状态、工具执行、权限边界、审批、预算和停止条件；NestJS 提供应用组织机制，不替代这些 Agent 运行逻辑。普通数据库操作或固定上传流程不必每一步由模型决策。

现有 `request`、`gateway`、`prompts`、`domain` 作为可复用代码保留；逐步接入 NestJS，不创建新项目覆盖现有源码。模块目录在实际搭建前单独讲解。

## 6. 演示阶段的取舍

第六课已接入单 Bearer Token 认证。业务接口使用校验后的用户身份，模型工具通过可信运行上下文获得用户 ID。公开注册、复杂角色权限、管理后台和多人实时协作留待后续。

Agent 的预算、付费生成确认、任务停止和重复提交控制仍按课程实现；这些与是否有登录接口是不同问题。

界面先使用对话区、项目与素材列表、可编辑分镜列表，不引入无限画布、复杂时间线、完整历史对比或协同编辑。

## 7. 分享前范围与扩展

分享前主线目标：项目和草案持久化、真实资产查询、模型与工具反馈循环、上下文管理、Web/SSE/Trace、确认后的视频任务执行和 COS 产物预览。

Skill、MCP、RAG/Embedding、Memory 和回归验证按独立实验逐步补充，不要求每次业务运行调用全部能力。第 18 课的框架对照暂不做。AI Short Drama Workflow 留作 Skill 课程参考或集成候选。

评测 Agent、基于评测质量的模型路由、无限画布、复杂剪辑、完整版本历史与细粒度权限等留作扩展。Gateway 先手动及默认选择，再按模型能力、接口可用性和成本排序，不把接口支持等同于质量保证。

## 8. 调整后的课程节奏

1. 已完成前三课主线：真实文本请求、公共 HTTP 封装、提示词与 JSON 模式；第五课接通工具反馈循环。
2. 第四课前段补基础设施小节：NestJS 最小启动 → TypeORM/MySQL 连接 → 资产记录与真实样本 → COS 引用和访问验证 → 资产查询服务。
3. 第四课后段：`search_user_assets` 声明、注册、模型请求和真实数据库查询。
4. 第五课：工具结果回传与 Agent Loop；终端可以继续作为观察入口。
5. 第六至九课依次用独立会话学习历史读写、压缩、运行控制和 SSE/Trace。第十课先接项目归属与草案存储，再把项目列表、分镜和多会话对话栏接入 Web。第十一课的生成任务关联已确认的镜头版本。

基础设施扩展增加了配置、连接、持久化和联调工作，原 35–50 小时估算不再未经核算直接沿用。待 MySQL、COS 与 NestJS 最小链路验证后，根据剩余分享时间重新估算；不提前承诺全部功能在原时间内完成。

## 第四课基础设施补充

MySQL 使用 Docker Compose，本机只需 Docker 引擎，不安装 MySQL 服务。第一阶段准备连接与独立数据库健康检查，之后再做资产实体和迁移。工具主线为 `search_user_assets`，后续加入 `generate_image_asset` 补齐缺少的角色、场景或道具参考图；Web 可从素材库、分镜参考素材和对话进入，复用资产生成服务。

## 本地运行方式更新

NestJS API 和 MySQL 均使用 Docker Compose，宿主机 API 端口 3100，容器内 API 端口 3000，数据库内部访问 `mysql:3306`。默认开发镜像挂载源码，容器内安装依赖、编译与重启。当前验证限制和命令见[容器运行说明](./04-tool-definition-and-execution.md)。


## 数据库关系约定（2026-11-17）

- 表间使用逻辑关联，不创建数据库 `FOREIGN KEY`；保留主键、必要索引和唯一约束。
- 应用服务校验关联记录存在性和用户归属，相关写入用事务保证原子性；并发场景另行设计锁或版本控制，不能把事务当作自动引用完整性检查。
- 删除由应用显式编排，不依赖数据库级联或默认 ORM cascade。所有写入口均需遵守关联检查约定。
- TypeORM 优先使用标量关联列；若使用关系装饰器，设置 `createForeignKeyConstraints: false`。生成迁移后检查不得出现意外的外键。
- 新会话表以 `session_id` 为主键，消息表以 `message_id` 为主键并通过 `session_id` 逻辑关联。TypeScript 属性使用驼峰，通过列名映射。资产和会话的归属字段统一使用 `userId`，数据库列为 `user_id`。


## 第六课用户认证范围调整

用户授权补充 users、auth_tokens 以及单 Bearer Token 登录/注销，替代演示身份硬编码。密码加盐哈希，Token 仅保存哈希且有有效期，不实现双 Token；运维命令创建账号，不开放注册。此项覆盖早期“暂不实现接口鉴权”的范围约定。实际会话授权与历史读写仍需在后续小步接入，详见第六课讲义。
