# 第八课　控制一轮对话的工具调用次数

用户发来「从我的素材库搜索墨墨」。第五课已经跑通过这条链路：模型请求搜索，程序执行工具，模型根据结果回答。第八课解决其中的一个问题：如果模型拿到搜索结果后一直要求再查，程序在哪里停下来？

## 1. 沿着一次搜索读代码

用户向 `POST /api/sessions/:sessionId/turns` 提交消息。会话服务校验用户归属、读取已有对话，把历史和这次的消息交给 `AgentService.runWithHistory()`。每次进入这个方法，`toolCalls` 都从空数组开始。已有历史里的工具调用只作为模型的参考，本轮单独计数。[会话入口](../src/harness/session/session.service.ts) · [Agent Loop](../src/harness/agent/agent.service.ts)

读到历史筛选、回查和并发保存时，可以对照同一段对话里的四个序号变量。[第七课的会话消息序号示例](./07-context-compaction.md#四个变量怎样使用同一套会话消息序号)

假设本轮最多处理 5 个工具调用。这是项目的运行配置。模型的一次回复可能同时提出好几个调用，所以每次收到回复后、执行本批任何工具前，先检查两个数字：

```ts
if (toolCalls.length + response.toolCalls.length > MAX_AGENT_TOOL_CALLS) {
  // 添加一条给用户看的停止提示，结束本轮。
}
```

`toolCalls.length` 是本轮此前已受理的调用数。`response.toolCalls.length` 是模型这一次刚提出的调用数。通过检查后，程序才记录本批调用，逐个执行，并保存对应的工具结果。参数字符串无法解析为 JSON 时，程序把失败原因返回模型，这次尝试也占一个名额。[上限配置](../src/config/agent-run-control.ts) · [调用计数与停止判断](../src/harness/agent/agent.service.ts)

| 此前已处理 | 模型这次的回复 | 程序的动作 |
|---:|---|---|
| 0 | 请求搜索一次 | 执行搜索，把结果交给模型 |
| 4 | 请求搜索一次 | 执行第 5 次搜索，把结果交给模型 |
| 5 | 根据已有结果给出回答 | 返回 `completed`，用户看到模型的回答 |
| 5 | 还要搜索一次 | 返回 `stopped`，第 6 次搜索没有执行 |
| 4 | 同时提出两个调用 | 整批停止，实际处理数仍为 4 |

为什么在已处理 5 次后还要再问模型？用户要的是搜索答案。模型需要读到最后一个工具结果，才有机会把它写成回答。所以限制的是工具调用数。若模型每次只请求一个工具，常规回答模型最多调用 6 次。第七课用于摘要的额外模型调用单独计数。

## 2. 停止后，用户和数据库各得到什么

例如模型已经查了 5 次，又提出第 6 次搜索。Harness 在执行前拦下它，在本轮消息末尾追加一条助手提示。接口返回 `status: "stopped"`、`reason: "tool_call_limit"`、可展示的 `text`，以及前 5 次调用和对应结果。客户端可以把 `text` 显示在这次对话里。

会话服务沿用第六课的事务，把本轮用户消息、已受理的工具调用、配对结果和停止提示依次写入 `session_messages`。这样下一轮读回历史时，每个已记录的调用都有结果。用户再发一条消息，会开启新的一轮，调用额度从 0 重新计数。独立入口 `POST /api/agent/run-once` 共用相同的停止判断，只返回这次运行结果。[运行结果类型](../src/harness/types.ts) · [会话存储](../src/harness/session/session.service.ts)

## 3. 验证

在项目根目录运行：

```sh
pnpm build
node --test --test-reporter=spec tests/agent-run-control.test.mjs
```

测试固定模型提出的调用，复用素材搜索工具和工具注册器。这样可以稳定复现四种情况：第 6 次被拦且下一轮可继续、恰好 5 次后正常回答、同一批整体超限，以及参数解析失败也计数。断言同时检查搜索实际执行了几次、哪些调用有配对结果，以及向用户返回的状态。[第八课回归测试](../tests/agent-run-control.test.mjs)
